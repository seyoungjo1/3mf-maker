# 글과 이미지를 만드는 방법

## 기본 방향

이 계정은 개인 취미로 만들고 고쳐 보는 과정을 기록하는 공작실입니다. 결과물만 소개하기보다 **무엇에서 시작했고, 어떤 문제 때문에 무엇을 바꿨는지**를 보여줍니다. 말투는 편안한 한국어 존댓말로 씁니다. 농담은 억지로 넣지 않습니다.

## 작성 순서

1. 프로젝트 README·설계 기록·검사 결과와 사용자 설명을 읽습니다. 이전 시도, 바꾼 이유, 현재 상태를 메모합니다.
2. 기존 계정의 실제 게시물 이미지를 확인합니다. 캡션만 보고 이미지 스타일을 안다고 판단하지 않습니다.
3. 사용할 실제 캡처를 고릅니다. 표지 → 모티브 → 변경 과정 → 결과 영상 → 필요한 안내 순으로 이야기 흐름을 만듭니다.
4. 제목·짧은 설명·사진을 한 장 안에서 편집합니다. 표지 한 장부터 확인하고 나머지 장으로 확장합니다.
5. 이미지의 흐름에 맞춰 본문을 씁니다. 내부 버전명이나 검사 수치를 독자가 이해할 이야기로 풀어 씁니다.
6. 실제 크기와 휴대폰 크기로 글자·줄바꿈·겹침·영상 속도를 직접 확인합니다.
7. 미리보기 요청과 게시 요청을 구분합니다. 사용자가 게시를 요청하면 확정된 파일을 고정하고 API로 실행한 뒤 링크·첨부 수를 확인합니다.

## 캡처·폰트

- 배경은 흰색, 조명은 밝고 중립적으로 설정합니다. 제품의 홈·문양·경계가 읽혀야 합니다.
- 제품 형상은 실제 메시를 렌더합니다. 이미지 생성으로 형상이나 부품 수를 임의로 바꾸지 않습니다. 셔틀콕 같은 설명용 소품은 ‘수납 예시’라고 표시합니다.
- 제목은 기존 **Jua** 계열의 둥근 제목체를 유지합니다. 설명이 작다는 피드백을 제목 폰트 변경으로 해결하지 않습니다.
- 설명문은 **Gamja Flower**처럼 부드럽고 읽기 쉬운 한글체를 크게 사용합니다. 셔틀콕 게시물은 1080×1350 기준 설명 약 46~58px를 썼습니다. 글꼴마다 실제 보이는 크기가 달라 육안 확인이 필요합니다.
- 크기를 키웠으면 글을 줄이거나 배치를 바꿉니다. 마지막 ‘요’만 다음 줄로 떨어지거나 사진 위로 글자가 겹치지 않게 합니다.
- 참고 자료는 원 작업자와 출처를 표시하고, 초기 구상·최종 설계·실물 사진을 구분합니다.

## 본문 구조

**출발점 → 개선 과정 → 바꾼 이유 → 현재 상태**를 기본으로 합니다.

첫 문장은 무엇을 만들었는지와 관심을 끌 만한 발상을 짧게 말합니다. 본문은 각 변경의 원인과 결과를 연결합니다. 예를 들어 ‘몸통을 두 조각으로 출력합니다’에서 끝내지 말고 ‘높게 세워 출력할 때 진동으로 깨지는 문제를 피하려고 나눴어요’라고 설명합니다.

R9·v10·파일명처럼 독자에게 의미 없는 내부 표기는 캡션과 이미지 제목에서 뺍니다. 개발·검사 기록에는 남겨도 됩니다. 확인되지 않은 실제 출력 성공, 사용감, 수납 보장, 내구성을 주장하지 않습니다. 사용자가 직접 알려준 경험은 사용자 설명을 근거로 기록합니다.

해시태그는 주제·취미·제작 방식에 맞는 3~5개를 우선합니다. 같은 마무리 질문이나 팔로우 요청을 매번 붙이지 않습니다.

## 영상·GIF

- 사람에게 보여 주는 영상은 움직임을 알아볼 수 있는 속도로 만듭니다. 모델 회전을 빠르게 반복하는 데 그치지 않습니다.
- 셔틀콕통 수정본은 원본 움직임 대비 **5배 느리게**, 앞뒤 각 2초 멈춤을 넣어 **24초 MP4**로 게시했습니다.
- 실제 파일을 재생해 속도를 확인합니다. 길이만 늘리고 빠른 장면을 반복하는 방식은 피합니다.
- Instagram에는 GIF 원본 대신 MP4로 변환해 올립니다. 상태별 렌더를 실제 작동·실물 시험처럼 표현하지 않습니다.

## 마지막 안내와 AI 표시

이번 작업에서 사용자가 지정한 최종 문구:

> 개인 취미와 학습을 위한 작업이며, 브랜드 이름과 참고 이미지의 권리는 각 권리자에게 있습니다.
> 해당 게시글은 AI를 통해 작성되었습니다.

관련 안내가 필요한 게시물의 마지막 이미지에 넣고, 본문에도 AI 작성 사실을 표시합니다. 안내 문구만으로 브랜드·참고 이미지의 사용 허락을 받았다고 판단하지 않습니다. 이전에 논의했던 긴 비공식·삭제 요청 문구를 최종 요청과 상관없이 자동으로 붙이지 않습니다.

## 게시와 수정

게시 후 이미지·영상의 교체가 필요하면 새 게시물로 올리는 절차가 필요합니다. 기존 글을 어떻게 처리할지는 사용자 선택을 따릅니다. 셔틀콕통은 사용자가 기존 글을 직접 보관하고 수정본을 새로 게시하기로 했습니다. 보관 여부를 확인하지 않았으면 ‘보관 완료’라고 쓰지 않습니다.

폴더 이동·문서 수정은 게시 승인이 아닙니다. 게시 요청 파일과 게시 원장을 분리하며, 같은 post_id를 무조건 재게시하지 않습니다.


## 부품케이스 게시글에서 확인한 표현 기준

- 제목은 사용자 지정 이름 **나만의 로고 부품케이스**를 그대로 쓴다. 표지는 Jua 104px로 크게 배치한다.
- “마음에 걸려서”, “안타까워서” 같은 감상적인 계기 문구를 쓰지 않는다. “자석 이름표를 정리하고 옮기려고 만들었어요”처럼 용도를 설명한다.
- 실물 사진은 각각 한 번씩만 사용한다. 최종 요청에 따라 열린 사진은 표지, 닫힌 사진은 작은 글씨의 출력 문제를 설명하는 장에 배치한다. 나머지는 설계 화면과 느린 GIF 영상으로 구성한다.
- 잘된 부분과 함께 실제 출력 실패도 구체적으로 적는다. 무늬 있는 빌드 플레이트의 안착 문제로 작은 글씨가 찌그러진 점을 숨기지 않는다.

- 제목 크기를 바꾸면 설명 위치도 함께 조정한다. 제목과 설명을 절대좌표로 겹쳐 놓지 않는다. 표지 설명은 행간 1.4, 두 사진은 같은 상단선에 맞추고 전체 페이지를 확인한다.
