# 3MF 캡처·인스타그램 게시글 편집 지침

## 우선순위: 캡처의 품질

사용자 확인(2026-10-21): 참고 게시물에서 중요한 것은 농담보다 사진·캡처의 보여주기 방식이다. **캡처 구도·밝기·형상 전달을 먼저 완성하고 글을 맞춘다. 농담은 필수 요소가 아니다.**

- 흰 배경(#ffffff), 밝은 중립 조명과 연한 베드를 기본으로 한다. 어두운 부품의 측면·홈이 검게 뭉개지지 않게 하고 밝은 로고도 배경과 구별되게 한다.
- 전체 모습은 사선 뷰로 두께·앞면·받침이 함께 읽히게 한다. 형상은 화면의 약 70~85%를 쓰는 구도를 출발점으로 하되 긴 주차판은 비율을 왜곡하지 않는다. 이는 편집 기준이며 참고 이미지에서 실측한 값이 아니다.
- 전체 → 정면(글자·배치) → 옆면(기울기·받침) → 분리/조립(구조) 순으로 각 장의 역할을 다르게 한다. 같은 각도만 반복하지 않는다.
- 게시용 캡처에서 불필요한 UI·커서·선택 테두리·파일 경로·보고용 상태줄은 제외한다. QC 원본은 보존하고 경고를 숨겨 검증 성공처럼 표현하지 않는다.
- 휴대폰 크기로 축소해 로고·글자·부품 경계가 읽히는지 확인한다. 사진을 보지 않은 채 참고 사진과 같다고 보고하지 않는다.

추가로 읽은 자료: [MakerWorld 제작자들의 사진 가이드](https://forum.bambulab.com/t/the-ultimate-makerworld-photography-guide/109141)는 정돈된 배경·고른 빛·여백·전체/상세/사용/조립 전 사진의 역할을 설명한다. [DMaF Lab의 모델 촬영 지침](https://www.dmaf-lab.com/resources/photography-objects-models)은 시점과 근접 촬영이 형태·재질 전달에 미치는 영향을 다룬다. 실물 촬영 원칙 중 배경·시점·빛·구성만 렌더 캡처에 응용한다. 기존 Instagram 참고는 캡션만 확인한 상태이며 사진 전체 구성은 아직 검증하지 못했다.

## 필요한 게시물의 마지막 이미지: 취미 작업 안내

사용자 최종 기준: 안내는 매번 캡션에 붙이지 않는다. 브랜드·로고가 등장하거나 공식 제품으로 오해할 수 있는 게시물에만 **캐러셀의 마지막 이미지**로 넣는다. 그 외 게시물에는 생략한다. 마지막 안내 이미지를 붙일 경우 캐러셀 API 연결과 검증이 필요하며 단일 이미지 게시 구현만으로 완료라고 하지 않는다.

문구는 짧고 편하게 쓴다. 법률 고지처럼 긴 문장이나 딱딱한 제목은 사용하지 않는다. 제네시스 주차안내판용 기본 문구:

> 좋아하는 디자인을 제 방식으로 만들어 봤어요.
>
> 개인 취미로 만든 작업이라, 반복해서 만들거나 판매하려는 목적은 없어요.
>
> 제네시스 공식 제품은 아니고, 브랜드와 협업한 작업도 아니에요.
> 브랜드 이름과 로고의 권리는 해당 권리자에게 있어요.
>
> 권리자께서 삭제를 요청하시면 게시물을 내릴게요.

다른 브랜드 작업은 실제 브랜드명과 관계로 바꾸며, 판매·협찬 등 사실이 달라지면 문구도 수정한다. 안내가 필요하더라도 이미지마다 워터마크처럼 반복하지 않는다.

### 마지막 장의 폰트·배치

- 흰 배경에 진한 회색 글자. Noto Sans KR Regular/Medium 같은 단정하고 부드러운 한글 고딕을 우선한다. 글꼴은 배포본 라이선스를 확인하고 확보된 폰트 파일을 사용한다.
- 1080×1350 기준 본문 36~42 px, 행간 1.6~1.75, 좌우 여백 100 px 이상을 시작점으로 삼는다. 작은 글씨를 빽빽하게 넣지 않는다.
- 첫 문장만 44~50 px Medium, 나머지는 Regular. 전체 굵은 글씨·딱딱한 명조·가느다란 손글씨·법률 문서형 박스는 피한다.
- 왼쪽 정렬과 짧은 문단을 기본으로 한다. 어절을 중간에서 자르지 않고 휴대폰 크기로 실제 가독성을 확인한다. 과도한 자간·로고 장식은 넣지 않는다.
- 모델을 보여주는 앞 장들은 이미지에 집중하고, 안내는 마지막 장에서 조용히 전달한다.

### 내부 권리 검토 메모 — 이미지에 그대로 넣지 않음

이 문구는 목적과 비공식 관계를 설명하며 이용 허락이나 법적 면책이 아니다. [제네시스 공식 저작권 안내](https://www.genesis.com/kr/ko/terms-of-use/copyright.html)는 브랜드 사용에 사전 허락을 요구한다. 비상업적 취미 또는 사후 삭제 의사만으로 사용이 허용된다고 단정하지 않는다. 권리 허락 확인 또는 로고 없는 독자 디자인이 더 보수적인 선택이다. 웹사이트 정책과 개별 행위의 법률상 판단은 구분한다.

## 목표와 말투

3D 모델이 어떻게 생겼는지와 왜 그렇게 설계했는지를 함께 보여준다. 기본 말투는 한국어 존댓말, 직접 만든 사람이 작업 과정을 설명하는 자연스러운 톤이다. 과장 광고, 상투적인 감탄사, 무관한 유행 해시태그는 피한다. 사용자가 별도 톤을 지정하면 우선한다.

게시글 작성은 자동 게시의 부속 작업이 아니다. 이미지와 함께 검토할 독립 결과물로 취급한다. 같은 도입부·마무리·해시태그 세트를 매 게시물에 반복하지 않는다.

## 사용자 참고 게시물에서 확인한 스타일 (2026-10-21)

참고: https://www.instagram.com/p/Dbk0guCoPNV/ — sy_3dprintgarage의 포션 키링 게시물. GitHub Actions에서 공개 페이지 description/og:title을 읽어 캡션을 확인했다. 이미지 전체 및 캐러셀 순서는 확인하지 않았으며 좋아요 수로 효과를 판단하지 않는다.

- 첫 문장은 판타지 소재를 실제 제작물로 연결하는 짧은 후킹 문장이다.
- 이어서 무엇을 만들었는지, 사용 재료가 무엇인지 구체적으로 소개한다.
- 색·투명감 같은 시각적 특징에 가벼운 농담을 더해 공작실다운 친근함을 만든다.
- 제작 과정은 3D 프린터·몰드처럼 짧고 이해하기 쉬운 말로 설명한다.
- 이모지는 강조 위치에 소량 사용하고 마지막에는 소재·기술에 맞는 해시태그를 붙인다.

3MF 캡처 글에도 **눈길을 끄는 첫 문장 → 무엇을 설계했는지 → 눈여겨볼 특징/작업 이야기 → 현재 상태 → 관련 태그** 구조를 우선 적용한다. 짧은 글이면 문단을 억지로 늘리지 않는다. 참고 글의 문장을 그대로 반복하거나, 유쾌한 톤을 위해 없는 기능·실출력 경험을 만들어내지 않는다. 렌더만 있을 때는 실제 제작물인 것처럼 표현하지 않는다.

## 소재 수집

프로젝트 README, 최신 REPORT/QC, 설계 스터디, 승인된 렌더와 실제 출력 사진을 읽는다. 다음 항목을 출처 경로와 함께 초안 메모에 적는다.

- 프로젝트명·버전·이 물건으로 해결하려는 문제
- 캡처에서 실제 보이는 특징 한두 가지
- 설계 의도 또는 수정 과정에서 배운 점 한 가지
- 검증된 크기·재료·출력 조건(게시글에 유용할 때만)
- 상태: 설계 중 / 렌더 확인 / 슬라이서 확인 / 실제 출력 / 실사용

기록에 없는 작업 동기·사용 경험·출력 시간·가격·내구성·완성도 수치를 지어내지 않는다. QC 통과는 실출력 성공과 다르다. 재료가 PLA여도 금속처럼 보이면 '은색 포인트' 등으로 설명하고 금속 제품이라고 쓰지 않는다.

## 이미지 준비

1. 첫 장은 형상이 한눈에 읽히는 전체/사선 뷰. 핵심 부분이 작으면 상세 뷰를 선택한다.
2. 여러 장이면 전체 → 특징 확대 → 분리/조립 → 제작 과정 순서를 기본으로 하되 게시 의도에 맞춘다. 캐러셀 수량은 API의 현재 한도를 확인한다.
3. 게시용 사본으로 여백·배경을 정리한다. 크롭 때문에 부품이나 치수 정보가 잘리지 않았는지 미리 본다. 원본 QC·렌더를 덮어쓰지 않는다.
4. 정지 이미지는 JPEG/sRGB로 준비한다. 편집 기본 캔버스는 1080×1350(4:5) 또는 1080×1080이며 이는 편집 선택이다. 실제 API 지원 비율·용량은 게시 전에 별도 검증한다.
5. 모니터 UI·파일 경로·계정명·전화번호·번호판·고객 정보가 노출되는지 확인한다. 공개용 더미 정보로 만든 캡처를 우선한다.
6. AI 이미지 도구로 제품 형상·부품 수·결합 구조를 바꾸지 않는다. 캡처는 실제 작업 결과를 표현한다.
7. 렌더는 캡션에 '3D 렌더' 또는 '설계 미리보기'라고 밝힌다. 실출력 사진과 함께 쓰면 어느 장이 어느 것인지 명시한다.

## 글 구성

- 첫 문장: 물건의 용도, 눈에 띄는 설계 특징, 구체적인 수정 이야기 중 하나로 시작한다. 이미지를 보지 않아도 무슨 작업인지 알 수 있게 한다.
- 본문: 설계 의도 → 사진에서 볼 부분 → 현재 제작 상태 순서가 기본이다. 게시 목적에 맞게 순서를 조정한다.
- 길이: 기본은 짧은 문단 2~4개. 상세 설명이 필요한 경우 늘리되 기술 보고서를 그대로 붙이지 않는다.
- 마무리: 다음 제작 단계나 실제로 궁금한 질문 한 가지를 선택한다. 매번 좋아요·팔로우를 요구하지 않는다.
- 해시태그: 우선 3~5개의 직접 관련 태그로 시작한다. 플랫폼의 현재 제한을 넘기지 않으며 노출 증가를 보장하지 않는다. 프로젝트 특성·용도·제작 방식에 맞춰 바꾼다.
- 다운로드·판매·오픈소스·프로필 링크 문구는 실제 공개 URL과 사용 권한이 확인된 경우에만 넣는다. 캡션 URL이 클릭될 것으로 전제하지 않는다.
- 브랜드 모티브 작업은 개인 제작임을 정확히 설명한다. 공식 상품·제휴라는 표현을 지어내지 않는다.

## 게시별 초안 패키지

게시할 때마다 다음을 묶어서 준비한다.

| 항목 | 내용 |
| --- | --- |
| 출처 | 프로젝트·버전, README/REPORT, 선택한 원본 캡처 경로 |
| 이미지 | 게시 순서와 공개용 파일, 렌더/실사진 구분 |
| 본문 | 바로 게시할 최종 캡션과 해시태그 |
| 대체 텍스트 | 물체의 형태·색·배치 등 이미지 설명, 해당 API 지원 시 반영 |
| 사실 검토 | 출력 상태·치수·재료 등 주장과 근거 |
| 실행 | 대상 username, 게시 시각(Asia/Seoul), post_id, 게시 요청 범위 |

이미지/문구를 준비한 다음 대상 계정과 게시 요청이 확정되어 있을 때 실행한다. 단순 캡처 생성, QC 완료, 커밋 또는 push를 게시 트리거로 삼지 않는다. 게시 승인 후 이미지·본문이 변경되면 변경 내용을 알리고 기존 승인 범위에 해당하는지 확인한다.

## 실제 계정 이미지 비교 결과 — 2026-10-21 추가

최근 6개 게시물의 첫 두 이미지(총 12장)를 공식 API로 읽고 육안 확인했다. 포션 키링·카라비너·부적 키링·셔틀콕 클리커·클리커·그립 작업이다. `benchmark/status.json`에 원문 링크가 있다. 기존 문서의 '캡션만 확인'은 최초 조사 당시의 한계이며 이번 비교로 보완했다.

계정의 실제 특징은 둥근 한글 제목, 핵심 단어의 색 강조, 사진 위의 짧은 자막, 결과물과 제작 과정의 연결이다. 그라데이션 띠와 두꺼운 외곽선이 반복된다. 새 시안은 친근한 둥근 제목을 유지하고 배경·강조색·여백을 통일하며 외곽선과 과한 설명을 줄인다. 제목 Jua는 OFL 배포본을 사용한다.

제품 형상이 중요한 최종 시안은 기존 메시를 표준 `mm render`의 `presentation=True`로 캡처한 뒤 문서 레이아웃에 삽입한다. 생성형 이미지로 제품 구조·문양을 재해석하지 않는다. 렌더 원본은 보존하고 게시용 캡처에서 격자·상태줄만 제외한다. 원형을 바꾸지 않은 실제 캡처인지 확인하고 PC·휴대폰 크기에서 글자와 클리핑을 검토한다. 현재 시안과 캡션은 `previews/shuttle-r9/`에 있다. Instagram에는 게시하지 않았다.
