### 1-1. 클릭커·키캡 스템 — 다른 도안을 봤어야 했다(v1·v2 실패, 2026-10-24)
- **KeyV2**(rsheldiii/KeyV2, 가장 널리 쓰는 오픈소스 키캡 도안) `src/stems/cherry.scad`·`functions.scad`·`settings.scad` 실측:
  - 스템 바깥 `outer_cherry_stem = [7.2, 5.5] − 2·slop`(slop 0.35) → 6.5 × 4.8, `offset(r=1)` 둥근 직사각. 7.2×5.5 는 MX 슬라이더 크기 — **스템이 눌릴 때 슬라이더와 함께 하우징 구멍 속으로 들어간다.**
  - 십자 `cherry_cross(slop)` = [4.03+s, 1.25+s/3], [1.15+s/3, 4.23+extra_vertical(100)] — 세로 날이 스템을 관통해 반으로 갈라 끼움을 부드럽게(스템이 약해 보여도 일부러). inner slop 0.2.
  - 깊이 `$stem_throw` 4, 입구 베벨 offset 0.4 → 0 / 높이 0.5("첫 층 눌림 방지").
  - `$stem_inset = 0`: **스템 바닥 = 키캡 바닥 = 베드** — 십자 구멍이 베드에서 위로 뚫려 서포트가 없다. 받침(`$support_type = "flared"`)은 throw 위에서 윗판까지.
- v1 실패: 버튼 밑을 하우징 둘레 0.4 틈 계단 구멍으로 파서 MX 하우징(15.6)에 걸림.
- v2 실패: 천장에 ⌀5.6 튜브를 매달아 (1) 정방향 출력 시 튜브가 공중에서 시작 → 서포트가 십자 구멍을 막아 심지가 안 들어감("거꾸로"), (2) ⌀5.6 은 슬라이더 구멍 폭 5.5 보다 커서 누를 때 걸림.
- v3(KeyV2): 버튼 밑면(z 30) = 스템 바닥 = 뗌 상태 슬라이더 윗면(플랜지 + 6.2). 하우징 자리 18.6□ × 4.9. 소켓 윗면 z 23.8, 하부 구멍 바닥 z 15.3, 치마는 뗌 상태에서 하부 구멍에 6 mm.
- 사용자 기록(3d-print `generate_worker.py`)의 가동범위 계산(소켓 타워·하부 벽·스커트 중 먼저 닿는 것, 스템 물림)은 그대로 쓴다.

## 2. Tripo API — 배운 것
- **`model_version` 을 안 주면 서버 기본 v2.5-20250123** 으로 돈다(1·2차가 이것이라 "형편없다" 지적). v3.1 은 `v3.1-20260211`, `geometry_quality: "detailed"`. `tools/tripo_run.py` 기본값으로 고정. 버전 이름은 틀린 파일 토큰으로 보내 '이미지 비어 있음'(2003)이 오면 버전은 통과한 것(크레딧 0).
- **앞뒤좌우 그림**: `type: generate_multiview_image`(file 1장) → output `generate_multiview_image.{front,left,back,right}_view_url`. 이 4장을 다시 올려 `multiview_to_model`(files 4개 순서 앞·왼·뒤·오) v3.1 detailed. 사진 1 → 4방향(옆·정면·반대 옆·꼬리) → 발가락·등껍질 테두리·끈 구멍까지 나옴(v2.5 단일 사진은 바닥 너덜·면 뭉개짐).
- 크레딧: 생성 20(v2.5) / 4방향 그림 10 / v3.1 detailed 다시점 40.
- 세션 프록시: `api.tripo3d.ai` 는 키 주입, **결과 호스트 `tripo-data.*.tripo3d.com` 은 막힘** → `{"task_id": …}` 요청 파일을 push 해 Actions `tripo-run` 이 받아 커밋(크레딧 0).
- 입력 사진 정리(`scripts/prep_tripo_input.py`): 다른 제품·끈은 배경색으로 칠하고, 제품 위를 지나는 빨간 끈은 OpenCV inpaint.

## 3. Blender(bpy 5.2.3, 헤드리스 파이썬 모듈)
- `pip install bpy==5.2.3`(파이썬 3.13 venv에서 동작) — GUI 없이 glTF 가져오기·Decimate·Boolean.
- **Boolean 솔버는 MANIFOLD**: EXACT 에 부조 조각 수백 개를 컬렉션으로 넣으면 231 GB 할당으로 죽었다. 부조는 manifold3d 로 한 덩어리로 묶은 뒤 Blender 불리언 한 번.
- 둥근 사각 링 로프트(꼭짓점 수 고정)로 하부 단면 굴곡을 만든다: 받침띠 → 1/4 원 턱 → 몸통 → 어깨 → 턱 → 구슬띠 → 오목 경사(반폭 34 → 29.5, (1−t)^1.7) → 목대. 위로 갈수록 안으로만 물러나 오버행 0.
- **세운 면 부조(구름무늬)의 오버행 처리**: 깊이 t 의 단면 = P ∩ (P 를 위로 1.74·t 옮긴 것) → 아래로 향한 모든 모서리가 층당 0.115 로 물러난다(홈 속 천장 포함). 판(0.2 간격)은 전부 몸통 속 0.4 에서 시작해 겹쳐 쌓는다 — 판끼리 맞대면 경사면 휨(현 처짐) 때문에 틈이 생겨 조각 81개로 갈라졌다. 경사면은 수평 돌출 + `subdivide_to_size(1.5)` 로 곡률을 따라가게.
- 구름 모양: 머리 원 5개 + 가늘어지는 꼬리 + 말림, 소용돌이 홈 0.6(최소 획 0.8). 폴리곤 999점 그대로 판 9장 → 면당 115k 삼각형 → `simplify(0.03)` + 판 0.2 로 하부 전체 10만 면.

## 4. 사용자 결정
- "거북을 왜 잘라 — 저대로 올리면 된다, 간섭만 안 받게 전체 크기를 조정" → Tripo(거북 + 인 몸통)를 **그대로** 버튼으로, 배율만(인 몸통 긴 변 50 → ×63.1). 인 몸통은 직사각(실측 0.598 × 0.790, 넓이/외접 사각 0.93)이라 하부 구멍도 직사각(37.8 × 50 + 0.3/쪽).
- "아래쪽에만 구멍 같은 위치에" → 몸통 속을 통째로 비우지 않고, 스위치 자리 2곳만 계단 구멍(A 20 정사각 = 소켓·플랜지, B 14.8 = 하우징, 천장에 튜브). 몸통 밑에는 같은 윤곽의 치마를 연장(구멍 속이라 안 보임).
- 대각 2개: 직사각 몸통 안이라 (±6, ±11) — 소켓끼리 y 간격 22(≥ 19), x 로 12 비낌.
- "공차는 잘 줘야" → 버튼 ↔ 구멍 0.3/쪽(Tripo 겉면 최대 윤곽 기준이라 실제 틈은 더 큼), 소켓 14.4(스위치 13.95), 십자 1.35/4.2(기록값).
